One machine. One agent. One record.

Harrier ties every Wazuh agent to the hardware it runs on, revives agents that hang or drift, and keeps your manager's inventory free of duplicates and ghosts.

Install Harrier Read the docs
  • Linux and Windows 7+
  • x86 and x64
  • 0.6 MB, no dependencies
  • No credentials on endpoints

Install with one command

The installer checks Harrier against SHA256SUMS, fetches the official Wazuh agent, enrolls it under its hardware-bound name and starts the harrier service. Run it again to upgrade; when nothing is new, nothing changes.

curl -fsSL https://github.com/omidiyanto/harrier/releases/latest/download/install.sh \
  | sudo sh -s -- --manager 10.0.0.5 --group linux --wazuh-version 4.14.9

x86_64 or i686, as root. The Wazuh agent version must be 4.x up to 4.14 and not newer than your manager.

[Net.ServicePointManager]::SecurityProtocol = 3072; & ([scriptblock]::Create((New-Object Net.WebClient).DownloadString('https://github.com/omidiyanto/harrier/releases/latest/download/install.ps1'))) -Manager 10.0.0.5 -Group windows -WazuhVersion 4.14.9

x64 or x86, in an elevated PowerShell 3.0 or later. Windows 7 and Server 2008 R2 need WMF 5.1.

sudo HARRIER_API_PASSWORD='...' ./harrier-linux-x86_64 setup-server \
  --api-url https://127.0.0.1:55000 --api-user harrier

On the manager, with a least-privilege API user. The first run only shows what would change; after that, harrier-reconcile cleans the inventory every hour.

What the patrol handles

Every five minutes the endpoint service walks this playbook. The letter is what you will find in the logs.

  1. AHealthyNothing to do.
  2. BManager unreachableStands by. Keys are never touched and the agent buffers events.
  3. CAgent deleted on the serverThe agent re-enrolls; if it is still refused after an hour, Harrier re-enrolls it.
  4. DDisk cloned to other hardwareNew name for the new machine. The original agent is never touched.
  5. EHostname changedRe-enrolls under the new name; the old record goes only after the new one is active.
  6. FConfig tamperedRepairs the name and label in ossec.conf and restarts the agent.
  7. GAgent stopped or hungRestarts it after 10 minutes, with a 30-minute backoff.
  8. HGroup driftGroups move to the surviving record before an old one is deleted.
  9. IEvery network card replacedThe firmware id ties the new record to the old one, which is then removed.

A name the hardware can prove

Each agent is named after the machine itself, so two laptops with the same hostname never collide and a cloned disk never takes over the original's record.

FINANCE-07HostnameReadable at a glance in the dashboard.
-3fa94c1d02beHardware idSMBIOS UUID, BIOS serial and burned-in MAC addresses.
-77a1c0de9f31Firmware idUUID and serial only, so it survives new network cards.

Only the burned-in MACs of physical cards count. Wi-Fi randomization, USB docks, VPN adapters and VirtualBox, Hyper-V or Docker interfaces never change the name, and placeholder firmware values are ignored.

The full hardware id travels with every alert as the agent label harrier_hwid. A VM cloned without a new BIOS UUID is reported, never deleted.

How it fits next to Wazuh

Endpoints hold no Wazuh credentials and open no ports. Only the reconciler on the manager talks to the Wazuh API, as a least-privilege user over a pinned certificate.
